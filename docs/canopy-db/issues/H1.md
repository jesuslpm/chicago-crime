# README: the "Multiple Databases" example sets `page_cache_size` but never uses the options

## Summary

The third example of the README ("Multiple Databases with Atomic Cross-Database Commits"), which is also the
crate's front page on docs.rs, builds an `EnvOptions` with a 1 GB page cache but then opens the environment
with `Environment::new`, which does not take those options. The setting has no effect, while the comment next
to it suggests it does.

## Version

- canopydb 0.2.5 (README of the published crate)
- Found while reading the documentation; not platform specific.

## Steps to reproduce

Read the README of canopydb 0.2.5, example "Multiple Databases with Atomic Cross-Database Commits", lines
151–155:

```rust
let _dir = tempfile::tempdir().unwrap();
let mut options = canopydb::EnvOptions::new(_dir.path());
// all databases in the same environment will share this 1GB cache
options.page_cache_size = 1024 * 1024 * 1024;
let env = canopydb::Environment::new(_dir.path()).unwrap();
```

`options` is not used again anywhere in the example.

## Expected

The example opens the environment with the options it has just configured, so the cache size it sets is the
one the environment uses.

## Actual

The environment is opened with `Environment::new(_dir.path())`, so `options` is discarded and the page cache
keeps its default size. In the example itself this goes unnoticed, because the value it sets (1 GB) happens to
be the documented default of `EnvOptions::page_cache_size`.

## Impact

Readers copy this example as the way to configure an environment. Anyone who adapts it to bound memory, for
example with a 64 MiB cache on a memory-constrained host, believes the cache is limited when it still grows up
to the default; the difference shows up only as unexpectedly high memory use.

## Possible fix

Open the environment with the configured options:

```rust
let env = canopydb::Environment::with_options(options).unwrap();
```
