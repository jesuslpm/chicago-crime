# Docs: the default page cache size (1 GB) is not mentioned in the README

## Summary

The page cache grows on demand up to 1 GB by default, but the README (which docs.rs shows as the crate's front
page) does not say so. The only place that gives the default is the doc comment of
`EnvOptions::page_cache_size`. The README mentions 1 GB only in the comment of the "Multiple Databases" example,
where it reads like a value chosen for that example rather than the default.

## Version

- canopydb 0.2.5 (README and `src/options.rs` of the published crate)
- Found while reading the documentation; the memory figures below were measured on Windows 11.

## Steps to reproduce

1. Read the README of canopydb 0.2.5: no section states a default cache size or that the cache is the main
   memory consumer.
2. Read the documentation of `EnvOptions::page_cache_size` (`src/options.rs`), the only place with the default:

   ```text
   Database pages read from the Database files are cached in the page cache.

   Note that all databases in the same Environment share the page cache.

   Default: `1 GB`
   ```

## Expected

The README (for example next to the first example, or in a short "Configuration" or "Memory usage" note) says
that the page cache defaults to 1 GB, is shared by all databases of an environment, and is set with
`EnvOptions::page_cache_size` through `Environment::with_options`.

## Actual

The default is only discoverable by reading the `EnvOptions` field documentation. As a measure of what it means
in practice: reading every tree of a 3.3 GB database (about 52 million entries in six trees) with the default
options reached a peak of 1,161 MiB of memory, against 73 MiB with the cache limited to 64 MiB.

## Impact

The default dominates the memory footprint of any read-heavy workload, so it is the first number an embedder
needs for a memory budget (containers, desktop tools, several processes on one host). Without it on the front
page, the footprint surprises users in production rather than at design time. Together with the README example
that sets the cache size but does not apply it (reported separately), it is easy to end up with the 1 GB default
while believing a smaller limit is in place.
